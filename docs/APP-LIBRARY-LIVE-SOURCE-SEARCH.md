# 应用库：在线来源反查（基于 v1.0.20261031.6 增强源码）

## 为什么不再用离线库判定“未匹配”

内置约 5,819 个包名仅是历史快照，且并非完整开源应用名单。离线未命中只能显示“尚未在线检查”，不能表示网上没有源码。手动保存的已确认来源、关联项目、待确认项目不会因在线搜索失败被覆盖。

## 当前在线查找过程（需用户点击，不批量扫描所有已安装应用）

1. 从本机取包名、应用名称；直接查询实时 GitHub 仓库名称、简介、README（包含 Fork 查询条件）。
2. Android 有效包名：调用 GitHub 受限的 REST 代码搜索，定位包含该包名的源码文件，并优先验证少量 `build.gradle`、`build.gradle.kts`、`AndroidManifest.xml` 的 `applicationId` 或 Manifest 包名。代码中仅提及包名视为弱线索；声明同一包名亦不证明 APK 同源。
3. 用户选择“深度搜索”时，扩大到不同构建配置文件并按包名查 F-Droid 在线记录，尝试从其 SourceCode 元数据确定候选仓库。
4. 找到候选后，可再通过既有“调查来源”“关联项目”“查看 Fork”与“检查安装包发布位置”做交叉核实。
5. 保存在线搜索时间、候选数和不完整标记；不会自动把排名第一的仓库当成已确认来源。

## API 安全与覆盖边界

- GitHub 的 `/search/code` 需认证，一般上限为 **10 请求/分钟**；新增源码查询之间至少间隔 7 秒并走现有限流保护。对 `403/429` 不自动无限重试。
- GitHub 代码搜索不保证覆盖 Fork、非默认分支、较大或未索引文件；当结果超出第一页时显示不完整提示。
- Releases 的 Assets 元数据只提供附件名、大小等，**通常不包含 APK 内 Android 包名**。若要确认二进制的包名，需要下载用户选定的 APK 并在本地解析、核对版本及签名。不能把 Release 文件名冒充 APK 包名。
- F-Droid 仅覆盖其收录范围，网页版还可能受跨域与网络限制，查询失败不代表没有开源仓库。
- 与本机应用有关的 GitHub 和 F-Droid 在线查询只有用户主动触发；不会未经选择将全部本机包名批量发送到网络。
- 来源发现是一条证据链，确定软件对应某个 Release 还需验证 APK 内容/发行来源及签名记录。

## 不变的现有功能

Android 本机应用扫描、图标、系统应用开关、修改版版本比较、Fork 上游、安装包发布位置、快捷构建、双代理及 PAT/OAuth 登录都不属于本轮替换范围。
