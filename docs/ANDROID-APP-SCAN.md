# Android 应用库扫描与系统应用开关

## 入口与行为

- Android 原生应用的「应用库」页面提供「扫描已安装应用」。浏览器网页端不具备 Android 包清单权限，继续使用手动添加或 JSON 导入。
- 使用 `PackageManager.getInstalledPackages` 查询**当前 Android 用户/资料空间**可查询的安装包，包含没有桌面图标和已停用的包；不能越过工作资料/其他用户的隔离，也不能读取其他应用的私有文件。
- Android 11+ 使用 `QUERY_ALL_PACKAGES` 以实现用户主动发起的应用管理清单扫描。此权限不出现运行时授权对话框，但应用市场审核可能限制使用。若发布 Google Play，必须判断其资格并提交用途声明。
- 扫描不自动发生，原生读取在后台线程进行；结果只交给本地 WebView，不通过网络发送。
- 默认关闭「显示系统应用」；开启后显示包含 `FLAG_SYSTEM` 或 `FLAG_UPDATED_SYSTEM_APP` 的条目（可能包括更新过的系统应用）。仅影响显示和筛选，不会卸载、禁用、隐藏系统包本身。
- UI 明确勾选后才导入本地应用库；已有记录用 Android **包名**去重，保留用户手动保存的仓库关联、版本和自签名备注。**不能依靠同名自动匹配仓库。**
- `signature` 为设备当前安装包签名证书的 SHA-256，并非源码对应性证明；包名与签名均可能因重打包、开发者轮换签名而变化。`installSource` 只是安装器标识。
- 当前筛选偏好存储在此设备本地 `localStorage`，默认隐藏系统应用；导入记录也保留 `isSystem`，方便以后筛选。

## 验证

1. Android 11、13、15 分别测试：扫描可列出普通应用、没有启动图标的包、可用系统应用；切换系统开关只改变当前列表。
2. 选择两款显示名称相同、包名不同的应用导入，应生成两条记录；重复扫描不覆盖已有链接。
3. 扫描后关闭「显示系统应用」，即使先前勾选过系统应用，也不能悄悄导入已隐藏条目。
4. 确认无 Android 原生桥接的网页上没有假扫描按钮。
5. Android 签名、Installer 元数据可能因为系统限制/厂商差异为空，应当允许继续导入。
6. 检查系统应用虽无法普通卸载，也能查看详情和开源项目关联，不将关联项目当作软件的已验证来源。
