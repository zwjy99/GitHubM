# 多线索溯源与页面恢复（1.0.20261031.5）

## 扫描与应用库

- “扫描 / 更新”位于“我的应用”标题旁。扫描刷新已有记录的版本、构建号、当前签名和安装来源，保留备注、手动关系和自定义名称。
- 来源目录命中的新应用会自动加入“我的应用”；未命中项可批量选择导入。
- “清除本次扫描结果”只清空临时扫描列表；“清空记录”经过确认后清空当前账号的应用库及溯源缓存，不会卸载应用。
- 包名、版本、签名 SHA-256、更新线索直接显示。来源地址参与搜索；筛选计数来自同一个应用列表。
- 手机端选择应用进入详情后有“返回我的应用”，避免详情藏在几百条记录下面；每批显示 50 条，筛选按钮换行显示。

## 证据链，而非包名即来源

1. 初始线索：F-Droid / IzzyOnDroid 目录、本机 APK 内部 GitHub 地址、用户记录的更新地址和手动提供的已知仓库。
2. 本机证据：base APK 的完整 SHA-256、版本名称与构建号、当前全部签名证书，以及有限 DEX、Manifest、资源和配置条目的内容指纹。只读取，不执行、不上传 APK。没有检查其它 split 包，不能据此认定整套分包相同。
3. 目录构建证据：目录记录的包名、版本、证书和文件哈希。不同目录的发布记录保留各自声明的源码位置，不把多个来源粗暴合并成同一作者。
4. 联网候选发现：包名、应用名称、简介/README 中对上游的引用；也尝试在源码里搜索包名。GitHub Fork 与独立复制代码后新建的仓库都保留为候选。
5. 关系区分：GitHub 的 parent/source 是平台关系；简介或 README 声明上游是作者声明；包内残留更新地址只是线索。它们都不等于实际安装来源或原始作者证明。
6. Fork 可按需继续翻页；仓库可筛选全部、有安装包、已检查范围没发现安装包、尚未检查。无包仓库不被删除。外部发布的包可手动提供 HTTPS 地址核对。
7. 每批检查 6 个仓库的最新 20 条 Release 附件，不自动下载全部 APK。需要完整文件对比时，由用户明确点击下载核对。候选 APK 在 Android 本机检查包名、版本、签名和文件内容，随后删除临时文件。
8. 本轮最多 400 个候选、每页 50 个 Fork；超出已检查范围保持未知。源码搜索可能受令牌权限或 API 规则限制；共享 API 额度、限流保护和停止操作仍然生效。

### 结果边界

- 同包名、同版本或指向同一个上游，不足以确认来源。
- 当前全部签名、包名及两个版本字段一致，仅标为构建关联，仍不自动确认作者。
- 自行签名导致证书不同，可以保留 DEX/资源相同的内容关联，不把它当成作者证明。
- APK 完整 SHA-256 一致，能证明是同一个文件；文件可能被多个仓库转载，不能据此唯一确定最初作者。
- 没有可区分证据，或候选构建存在冲突时，保留“来源未确认”。不能保证从没有身份线索、没有可核对发布记录的二进制中凭空恢复作者。

## README 与故障恢复

- 相对文档与图片链接按仓库、分支、当前 README 路径解析，不会落到 `file:///android_asset/README...`。
- 同仓库 Markdown（含中英文 README）在说明区域中读取。失败保留原说明，提供错误提示和浏览器链接。
- Markdown 原始 HTML 不得注入 base、脚本、iframe 或表单；说明和溯源区域有局部错误边界。
- 原生主 WebView 拦截离开 index.html 的本地文件导航。意外本地文件错误会恢复应用库，不需要强制退出。
- 网络任务最长等待 15 秒，可停止；候选 APK 下载限制 130 MB、读取超时与整体时限，支持取消，不阻塞 UI 线程。
